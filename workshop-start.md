# Start the Build Lab

Download and extract your assigned kit, open its folder in Codex, and give Codex this starting request:

> Read SKILL.md, references/project-framework.md and our assigned requirements. Use Codex with us throughout the framework: frame the problem; run the bundled five-minute Grill; help each of us prototype a local approach; compare and design our chosen solution; then build, test and iterate in small slices. Read the current Chatham Vibes build skill through references/ai-tooling-access.md before platform work, and load its relevant guidance as needed. Keep a short decision and evidence record, pause for our consequential product decisions, and do not treat an untested result as working. Help us prepare the shareback and reflect on improvements. Do not install plugins.

| Time | Work with Codex |
|---|---|
| 20 minutes — Explore | Frame the user/problem, run one shared Grill, then each person uses Codex to make a focused local React prototype. |
| 5 minutes — Choose and design | Compare the approaches, choose/combine useful ideas, sketch the workflow and data, and agree the first capability and acceptance check. |
| 55 minutes — Build and iterate | Use Codex to create/resume one team Vibes app. Build a small slice, inspect it, test it, give feedback, revise and recheck. Repeat. |
| 20 minutes — Verify | Use Codex for checks and critique; personally inspect a complete user journey and a meaningful failure/correction. Fix and recheck. |
| 20 minutes — Prepare | Use Codex and the presentation guidance to assemble three slides with actual evidence; rehearse the 5–7 minute shareback. |

The schedule is a target, not a guarantee. Test throughout rather than saving all testing for the end. During Explore, prototypes stay local and simulated, with synthetic or kit-permitted public data: no backend, live services, credentials or external scripts/fonts. Prepare the pinned React preview dependencies before Explore using [react-prototyping.md](react-prototyping.md); do not install arbitrary packages during the exercise. A useful interaction matters more than polish.

Before the shared Vibes build, use [vibes-setup.md](vibes-setup.md) and [technical-guide.md](technical-guide.md). Have Codex locate ai-tooling using [ai-tooling-access.md](ai-tooling-access.md) and read the current build skill, then the relevant frontend, jobs, data/AI or debugging guidance. Do not invent APIs or bypass platform restrictions. One team owns one app and coordinates deployments.

While Codex implements, teammates prepare checks, inspect sources, investigate the next decision or update [team-card.md](team-card.md). Rotate these responsibilities. When a test or user observation changes the plan, return to the affected framework decision and iterate; do not blindly restart everything.

Your assigned minimums remain authoritative. Optional ideas are not a backlog. Use [project-framework.md](project-framework.md) throughout and [presentation-deliverable.md](presentation-deliverable.md) for the shareback. Release only what you checked, state remaining limitations, and identify one improvement to how you would work next time.

## Design research

During Explore and individual prototyping, use [Design with intent](visual-design.md): study relevant product conventions and 2–3 strong examples, compare distinct compositions, then choose your own direction. Ask Codex to critique the rendered app during iteration. No additional deliverable is required.


## React handoff and workflow choices

Use [Local React prototypes](react-prototyping.md) to prepare the preview before Explore, compare approaches, and carry the selected source into Vibes. During Design and Plan, ask which steps need interpretation, explicit rules or human review; [AI and automation](ai-and-automation.md) offers an optional example. Keep the existing requirements and team record; no new deliverable is required.

## Record and submit

Read [project-log-guidance.md](project-log-guidance.md) at the start. Codex keeps evidence and known timing as you work; review the final log and add your reflection. Submit your app link, editable PowerPoint and log through the hub using [presentation-deliverable.md](presentation-deliverable.md).
