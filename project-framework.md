# Apply the seven-phase framework

**You own the purpose and decisions. Give AI focused work, check the result, and learn from use.**

Read the assigned minimum requirements first. Use the [extended guide](https://www.chathamvibes.com/vibe_apps/773/render#/workshop) when you need explanations or technical vocabulary. Keep one small project record and the [team card](team-card.md); the lab requires no extra report.

| Phase | Agent and team action | Evidence/output |
|---|---|---|
| Frame | Identify the user, task, intended benefit, and current difficulty. | Short brief; business success, not just a screen. |
| Define | Preserve every assigned minimum requirement. Record rules, exclusions, and expected cases. Read the bundled [workshop Grill skill](../skills/grill-me-workshop/SKILL.md) and run one shared round. | Team decisions and unresolved questions; do not invent answers. |
| Prototype | Each person explores a local React approach using synthetic or kit-permitted public data. Label simulated behavior. | Observations and design choices, not production claims. |
| Design and Plan | Compare approaches, choose a direction, map one complete user capability to the real helpers/data/jobs, and agree the first task. | Inputs, expected result, dependencies, boundaries, and checks. |
| Build and Verify | Start/resume one team app using the setup guide. Implement a bounded capability, inspect results, and repeat affected checks. | Implemented / verified / accepted kept separate. |
| Release | Prepare the checked version for the workshop demonstration; state what works and its limits. | App URL and honest evidence. Wider use is a separate decision. |
| Operate and Learn | Use feedback and observed results to choose one process improvement. | Q6: how you would assess the improvement, not invented productivity gains. |

Evidence can change an earlier decision. Update its requirement and dependent checks. Do not start all phases over for a small correction.

## Codex is your working partner in every phase

Use Codex to conduct Grill, make prototypes, compare and design, implement, test, critique and iterate—not just to generate code at the end. Analysts direct the work, answer product questions, inspect the actual result and decide whether it meets the need. Read the current Vibes build guidance before implementation and its relevant references when adding a capability. Use feedback and failed checks to revise the affected decision and recheck the result. Keep only the short project record/team card; no extra process deliverables are required.

## Direct one assignment

State the outcome, authoritative files/rules, boundaries, expected behavior, and completion checks. Ask the agent to report changes, checks actually run, observed results, and remaining gaps. Use fresh review for defects/omissions; verify that review too. Where automated testing is supported, write the expected behavior first, observe a meaningful failing check, implement, pass, then refactor/recheck. Otherwise use explicit manual acceptance cases; do not claim TDD or automated checks ran.

## Keep all three people working

While the agent builds, one person directs/integrates, one prepares independent expected results and runs checks, and one investigates the next decision or collects evidence for Q1–Q6. Rotate naturally; one agreed deployment at a time. Save a working version before significant change. Vibes UI history does not restore jobs or stored data.

## Time

Two hours total: Explore 20 minutes (including shared brief and roughly five-minute Grill), Choose 5, Build 55 (including app setup), Verify 20, Prepare 20. Test throughout. Present for 5–7 minutes afterward, show the app, answer Q1–Q6 in writing on the final slide, and submit the app URL, editable PowerPoint and reviewed project log/feedback through the hub.

## Decisions worth investigating for this project

- What should the user optimize when meetings compete for time?
- Which time-zone and travel-buffer assumptions must be visible?
- How should users inspect and override a proposed order?

These are candidate questions, not preset answers. Skip any settled by the brief or team.

## A concrete verification starting point

Try a new trip and an existing trip, check a travel/availability conflict, and adjust the proposal. Label synthetic travel estimates.

## Design research

During Explore and individual prototyping, use [Design with intent](visual-design.md): study relevant product conventions and 2–3 strong examples, compare distinct compositions, then choose your own direction. Ask Codex to critique the rendered app during iteration. No additional deliverable is required.


## React handoff and workflow choices

Use [Local React prototypes](react-prototyping.md) to prepare the preview before Explore, compare approaches, and carry the selected source into Vibes. During Design and Plan, ask which steps need interpretation, explicit rules or human review; [AI and automation](ai-and-automation.md) offers an optional example. Keep the existing requirements and team record; no new deliverable is required.
